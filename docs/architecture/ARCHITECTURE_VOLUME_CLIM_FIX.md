# Limage v1.9.11：真三维共享归一化修复

## 问题与根因

真三维的 Inline、Crossline 和 Time Slice 原来分别计算 `MapMin/MapMax`。同一色标因而在三张正交切片上代表不同的振幅值；当某一剖面包含边角填充值时，该剖面的局部范围会被异常端点控制，正常振幅全部挤到色标一端，画面接近全黑。

截图数据 `%SEISFORGE_TEST_VOLUME_ZERO_CORNER_FILE%` 的实际验收确认：IL 419 包含 `-999999` 无效填充值，局部范围为 `-999999 .. 41403.824`；XL 1220 的正常范围为 `-25801.560 .. 34949.528`。这不是合法的 0 振幅问题，而是独立归一化放大了无效端点的影响。

## 统一数据流

- `internal/segy.RenderTraceIndicesValues` 返回完成既有采样、平滑和 AGC 后的 `float64` 显示栅格；原 `RenderTraceIndices` 继续调用同一数据流并保持旧像素结果。
- 真三维会话保留当前 Inline、Crossline 的原始栅格；Time Slice 继续保留已有 `float32 + mask` 栅格。
- 三张当前切片合并计算一组共享 `MapMin/MapMax`，随后分别映射为相同色标索引。切换任何切片时，未移动的两张切片只做内存重映射，不重新读取 SEG-Y。
- 状态栏持续显示 `Shared min .. max`，用于确认三张切片使用相同归一化数值。
- A/B 模式中每个数据体内部的三张切片共享范围；A-B 残差仍保持原来的关于零对称范围，不改变残差定义。

## 0、无效值与显示参数

0 始终作为合法地震振幅参与统计，不按无效值删除。自动范围正确应用现有 `clip 99%`：在三张切片的合并分布上剔除两端各 0.5%，因此孤立的 `-999999`、极端边角填充值不会控制整个色标。`gain 0–49%` 在该共享分布上继续追加对称尾部裁剪。

手动最小/最大值优先级最高，启用后直接作为三张切片的共同范围。全常数或全零数据会围绕该常数扩展一个极小范围，避免退化为全黑或全白。Time Slice 原来的独立 1.15 倍 clim 放宽已移除；其半透明显示和所有三维相机、轴倍率、FOV、风格及交互保持不变。

## 验收结果

在截图数据的 IL 419、XL 1220、982 ms 三切片上：

- 修复前 IL 局部范围：`-999999 .. 41403.824`。
- 修复后共享范围：`-17091.194 .. 20156.115`。
- IL 纹理中接近黑端（色标索引 0–8）的像素从 `101,279` 降至 `5,210`。
- 三张切片的 `MapMin/MapMax` 完全相同，0 位于共同范围内部。

自动测试同时覆盖旧 `RenderTraceIndices` 像素一致性、0 中点、clip 99 哨兵过滤、gain、手动范围、Time Slice mask 和三面同步重映射。完整 `go test ./... -count=1` 通过。

发布文件为 `Limage_v1.9.11_volume_clim_x64.exe`，使用 Windows GUI 子系统构建，不覆盖 Phase 12 或其他旧版本。
