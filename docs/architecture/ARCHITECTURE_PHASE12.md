# Limage Phase 12 架构说明：伪三维首次冷加载加速

## 目标与冻结边界

Phase 12 只优化用户点击“伪”后、没有命中 `.ptx` 纹理缓存时的首次加载。没有增加后台预加载，也没有降低最终纹理分辨率、改变采样公式或牺牲显示质量。

下列行为和格式保持不变：20 套色标及顺序、gain/clip/AGC、自适应显示模式、相机与快捷键、XY AOI、时间范围、二维—伪三维联动、`.ptx v1`、`.cidx v1`、Recent 和所有 JSON。真三维渲染与 `volume_view.json` 未修改。

## 输出驱动的支撑计划

`internal/segy.TraceSupportPlan` 在读取 SEG-Y 前，根据输出纹理宽度预先计算每个纹理列的左、右支撑道和插值比例。支撑道按原始道序去重，未参与任何最终像素的道不会打开样点窗口、不会解码，也不会计算 AGC。

纵向采用同样的输出驱动原则：

- 最近道显示只保留每个输出行实际对应的源样点。
- 平滑显示保留每个输出行的上下支撑样点和原插值比例。
- AGC 必须使用所选时间窗的完整 RMS，因此 AGC 开启时仍解码完整支撑道时间窗，定义不变。

水平与纵向插值顺序、`float64` 运算、NaN/Inf 处理和幅值映射顺序与旧路径一致。IEEE Float、IBM Float 和整数 SEG-Y 均使用逐像素对比验证。

## 映射读取与回退 I/O

`ReadStrategySparseMapped` 是伪三维的默认冷加载策略。每个 Line Reader 延迟创建 Windows 只读文件映射，直接在映射区域内解码支撑道的样点窗口，避免逐道 `ReadAt` 和原始块复制。IEEE Float 与 32 位整数使用按格式、端序专用的内层解码循环；其他 SEG-Y 格式继续使用统一精确解码器。

资源约束如下：

- 同时最多四个映射 Reader。
- Reader 关闭时先解除视图映射、关闭映射句柄，再关闭源文件。
- 映射失败、不支持或测试强制禁用时，自动回退到稀疏批量 `ReadAt`。
- 回退块最大 16 MiB，相邻未使用数据的合并受 64 KiB 间隙和额外读取比例双重约束。
- 全局回退 I/O 同时最多八个块任务。

映射或回退失败只影响当前测线，不能泄漏映射句柄、Reader 或缓冲，也不能把过期结果送回窗口。

## 紧凑内存与分配控制

旧加载路径为每条支撑道创建一个 `[]float64`，并在每条线完成时产生大量短命大数组。Phase 12 将一条线的全部支撑道放入单个连续 `float64` 数组，通过固定步长索引访问；不再使用 `map[int64][]float64` 或逐道切片分配。

支撑道数组与输出幅值数组使用按 2 的幂分级的大缓冲池。缓冲中的每个元素在复用前均被新解码或新输出覆盖，不读取旧数据。单个复用缓冲最大 16 MiB，结合四条并行测线后，额外瞬时工作内存仍控制在 256 MiB 内；最终纹理继续遵守单线 `1024×1536` 和会话 192 MiB 预算。

## 并行 Z-buffer

`pseudo3d.RenderWithCancel` 保持原公共接口。渲染前只投影一次每条幕布的顶部、底部轨迹点，随后把输出图像切为互不重叠的水平屏幕带，最多使用八个 Worker。

每个屏幕带按与串行参考完全相同的幕布和三角形顺序执行透视校正纹理插值与 Z-buffer。不同 Worker 只写自己的行，因此不需要锁，也不会改变幕布交叉遮挡。坐标轴先绘制；幕布纹理和既有轮廓层的像素顺序保持原样。相机、AOI、时间窗或加载代次变化时，各 Worker 在幕布边界检查取消状态并尽快停止。

小窗口、高度不足 192 像素或少于四条幕布时自动使用串行路径，避免并发开销。

## UI 阶段与诊断统计

工作线程只通过窗口消息报告粗粒度阶段，UI 线程依次显示：

1. `规划支撑道`
2. `读取幕布`
3. `解码与映射`
4. `最终渲染`
5. `完成：总耗时 / 支撑道比例 / 缓存命中`

完成日志聚合记录总道数、支撑道数、逻辑读取字节、实际 `ReadAt` 字节、解码样点数、解码耗时、映射段数、回退段数和缓存命中数。日志不记录振幅或具体地震坐标，也不逐百分比写入。

## 实测对比

验收目录为 `%SEISFORGE_TEST_CROOKED_PROJECT_DIR%`，共 62 条有效测线、172,640 道。测试关闭伪三维纹理缓存，但不强制清空 Windows 文件系统缓存；每组运行五次并比较中位数。

| 指标 | Phase 11 | Phase 12 | 结果 |
|---|---:|---:|---:|
| 完整时间范围五次交错测试中位数 | 517.770 ms | 321.413 ms | 提速 37.9% |
| 开发前独立参考 / 稳态代表值 | 422.254 ms | 282.134 ms | 提速 33.2% |
| 完整范围支撑道 | 172,640 道输入 | 63,488 道 | 36.8% |
| 25% 时间窗加载 | 309.461 ms | 153.842 ms | 提速 50.3% |
| 62 幕布最终光栅（串行/8 Worker） | 112.081 ms | 37.854 ms | 2.96× |

完整范围逻辑支撑窗口为 594,198,528 字节，相比 1,657,469,976 字节源数据约为 35.9%。25% 时间窗的逻辑读取为 195,289,088 字节，纹理为 32,849,920 字节，均满足 Phase 11 时间裁剪预算；最终验收实测 0.154 秒低于 0.35 秒目标。实际耗时仍会受磁盘类型、Windows 文件缓存、杀毒扫描和同时运行程序影响，因此性能测试保留全部五次样本，并以同一进程内交错运行的中位数作为主要对比。

## 测试与发布

自动测试覆盖：

- IEEE、IBM Float、整数格式的映射/回退/旧路径逐像素一致。
- 最近道、平滑、自适应、AGC、gain 0–49%、完整及窄时间窗。
- 支撑道与支撑样点去重、映射失败回退、四 Reader 上限和关闭后零映射句柄。
- 并行光栅在透视/正交、四种风格和 1/2/4/8 Worker 下与串行参考逐像素一致。
- 渲染取消、过期代次、XY/时间裁剪、缓存和窗口状态回归。

发布文件为 `Limage_v1.9.10_pseudo_sparse_x64.exe`，使用 Windows GUI 子系统构建，不覆盖任何旧版本。
