Implemented contracts
- The pseudo-3-D page provides an enabled-only-when-valid "导出范围" action.
  At least one XY AOI or time window must be active, and only checked lines
  that are actually ready and visible in the completed curtain scene are
  included.
- Starting an export deep-copies canonical geometry and freezes line IDs,
  geometry fingerprints, calibration diagnostics, source metadata, trace
  indices, sample windows and requested ranges. Camera rotation, zoom,
  occlusion and later UI changes cannot alter a running export.
- Spatial planning reuses pseudo3d.ClipTrajectory. Every continuous re-entry
  keeps its interpolation support traces; overlapping supports are de-duplicated
  by walking the canonical trace geometry once in original acquisition order.
- Time windows are snapped independently for each line. No resampling or
  sample decode/re-encode occurs.
- Each selected line is written as an independent SEG-Y in a unique
  <project>_pseudo_crop_YYYYMMDD_HHMMSS directory. Duplicate source basenames
  receive a deterministic short suffix and existing artifacts are not reused.
- The public execution boundary rejects path traversal, absolute/invalid
  Windows names, device names, manifest/DAT name collisions, duplicate output
  names/sources and inconsistent trace/sample/source snapshots before creating
  an output directory.
- SEG-Y output uses a same-directory unique temporary file and performs
  Flush -> Sync -> Close -> reopen/structure/header/delay validation -> commit.
  The source path and aliases to the same file are rejected as destinations.
- Textual, binary and extended textual headers are copied; original trace
  headers, endian convention and IBM/IEEE/integer sample bytes are preserved.
  Only crop-required ns/dt/fixed-length/delay fields are updated.
- A modeless progress window reports line k/N, trace i/M and monotonic percent.
  Per-trace updates are coalesced latest-wins to avoid flooding the UI queue.
  Cancel deletes the current temporary output, preserves fully committed lines
  and writes every completed/cancelled/not-started status to the manifest.
- One line failure does not stop later lines. The original DAT is copied
  byte-for-byte and recorded with SHA-256. Completed, partial and cancelled
  batches write a JSON manifest with requested/actual/clipped ranges,
  calibration, geometry fingerprint, trace/sample mapping and output checks.
- The in-program pseudo-3-D help explains that "current view" means checked
  curtain lines, XY AOI and time window, not the camera frustum.
